From the transitor 프로젝트를 진행하기 위해 Verilog라는 것을 사용했습니다. Verilog는 HDL(Hardware Description Lnguage) 중 하나로써 FPGA(Field Programmable Gate Array)를 프로그래밍 하기 위한 언어입니다. 간단히는, 하드웨어 회로를 설계하기 위한 언어라고 이해하면 편할 것 같습니다.

이번 포스팅에서는 소프트웨어 프로그래머 관점에서 Verilog가 다른 프로그래밍 언어와 차이점은 무엇인지, 어떤 부분에 도움을 줄 수 있는지 알아보겠습니다.

What is Verilog?#

Verilog의 역사와 같은 지루한 내용들은 Verilog wiki를 참고하면 될 것 같습니다. 프로그래머 관점에서 살펴보면, 우리는 소프트웨어를 개발하기 위해 파이썬과 같은 소프트웨어 프로그래밍 언어를 사용합니다. 이런 언어로 작성된 프로그램은 컴퓨터가 이해할 수 있는 이진수형태로 컴퓨터 하드웨어에서 실행되는 순서죠.

하지만, Verilog는 소프트웨어가 아닌 하드웨어를 위한 언어입니다. 파이썬과 같은 프로그래밍 언어가 이미 존재하는 하드웨어에서 동작하는 프로그램을 만든다면, Verilog는 소프트웨어가 동작하는 하드웨어 자체를 만들 수 있습니다.

Why programmers have to know Verilog?#

사실 모든 프로그래머가 Verilog와 같은 HDL을 알아야 하는 것은 아닙니다. 특히나 고수준(High-Level)언어를 다루는 프로그래머 일수록 더욱 접할 기회가 없는 것 같습니다. 하지만, 프로그래머는, 어떤 종류이던, 결국 컴퓨터 하드웨어 에서 동작하는 소프트웨어를 만드는 사람입니다.

소프트웨어 프로그래머가 Verilog를 익힘으로써,

  • 하드웨어와 소프트웨어의 차이와 연결점을 이해할 수 있습니다.
  • 소프트웨어 최적화를 위한 하드웨어를 설계할 수 있습니다.
  • 사고방식의 확장을 할 수 있습니다.
  • 통합 설계 능력을 기를 수 있습니다.

Software Programming Language vs Verilog#

일반적인 프로그래밍 언어와 Verilog는 주요한 몇가지 차이점이 있습니다.

습관화된 프로그래머의 사고방식이 Verilog를 사용하는데 어려움을 만드는 것을 몸소 경험했습니다.

Sequential Logic vs Parallel Logic#

소프트웨어 프로그래밍 언어는 순차적으로 동작합니다. 이건 어떠한 언어를 사용하더라도 동일합니다. 프로그램은 결국 CPU명령으로 변환된 뒤에 명령어 단위로 순차적으로 실행됩니다. 하지만, Verilog는 본질적으로 하드웨어 동작의 병렬성을 모델링합니다.

다중 스레드 프로그래밍은 병렬실행이지 않은가?
멀티코어 CPU에서 명령어들을 병렬실행할 수 있지만, 개별 명령어의 실행은 여전히 순차적입니다.
다음 실행할 명령어의 주소를 저장하는 PC(Program Counter)는 하나의 값만을 저장할 수 있다는 것을 생각해봅시다.

Data Type#

소프트웨어 프로그래밍 언어에서 데이터 타입은 논리적인 구분입니다.

  • 정수(Integer)
  • 문자열(String)
  • 객체(Object)

논리적인 구분이란 것은 컴퓨터가 이해하는 요소가 아닌 사람이 이해하기 위한 요소입니다.

컴퓨터가 숫자, 문자, 객체를 구분할 수 없습니다. 컴퓨터는 0과 1만 이해할 수 있습니다.

하지만, Verilog는 하드웨어 동작을 기술하기 위한 언어이므로 하드웨어 구성 요소로 이루어져 있습니다.

예를 들어, reg와 wire는 하드웨어를 구성하는 기본 요소를 표현하는 Verilog 데이터 타입입니다.

  • reg : 플립플롭(Flip-Flop)이나 래치(Latch)와 같은 저장소를 모델링
  • wire : 단일 연결 선을 모델링

Data Assignment#

프로그래밍 언어에서는 일반적으로 변수할당은 곧 특정 메모리 공간에 어떤 값을 저장하는 것 입니다. 그리고 이 동작 또한 순차적으로 이루어 지기 때문에 하나의 메모리 공간에 두 개의 값을 동시에 저장하는 것은 불가능합니다.

아래와 같은 파이썬 코드에서,

# Sequential assignment in Python
a = 3
b = a + 2
c = a * b

c값을 계산하기 위해선 a와 b가 확정적이어야 합니다. 그렇기 때문에 어떤 변수를 사용하기 위해선 이전에 해당 변수에 값이 할당되어 있어야 하죠.

다중 스레드 프로그래밍에서는?
다중 스레드에서 동작한다고 하더라도 동일합니다.
임계영역(Critical Section)을 가지는 경우에도 문제가 되는 것은 베타성일 뿐, 각 스레드는 한번에 한개씩만 메모리에 접근할 수 있습니다.

하지만, Verilog는 두 가지 할당방식을 지원합니다.

Blocking Assignment in Verilog#

일반적인 프로그래밍 언어에서의 할당과 동일한 순차적인 할당을 의미합니다.

reg a, b, c;

always @(*) begin
  a = 3;
  b = a + 2;
  c = a * b;
end

각 변수, a, b, 와 c는 순차적으로 할당되어 c=15가 됩니다.

하드웨어에서는 AND/OR게이트, 멀티플렉서와 같은 **조합 논리(Combinational Logic)**의 설계에 주로 사용됩니다.

Non-Blocking Assignment in Verilog#

<=기호를 사용한 Non-Blocking 할당은 값 할당이 동시에 이루어 집니다.

reg a, b, c;

always @(posedge clk) begin
  a <= 5;
  b <= a + 2;
  c <= a * b;
end

변수 a, b, c는 현재 구문에서의 값에 의존적이지 않습니다. 변수 b를 할당할 때, 이전 문장인 a <= 5의 결과로 예상되는 5 + 2의 결과를 사용하는 것이 아니라, a의 이전 상태 값을 사용합니다.

지금은 이해가 어렵겠지만, 추후 포스팅되는 Verilog 프로그래밍 예제를 통해 이해를 도울 수 있을 것 같습니다.

즉, Non-blocking은 기본적으로 상태기반의 동작입니다.

하드웨어에서는 클럭(Clock)을 사용한 **순차 논리(Sequential Logic)**의 설계에 주로 사용됩니다.

Conclusion#

소프트웨어 프로그래머 관점에서 Verilog를 사용해보는 것은 하드웨어를 이해하는데 큰 도움을 줄 수 있습니다.
