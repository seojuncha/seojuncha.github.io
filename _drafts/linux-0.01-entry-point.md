최근 시스템콜 관련 프로젝트를 하면서 리눅스 내부 동작이 궁금했다.
하지만 최신의 리눅스 커널은 수많은 디바이스 드라이버와 추상화, 다양한 기능들과 엄청난 코드량으로 인해 운영체제로서의 리눅스 커널의 본질을 이해하기 어려울 것 같았다.

그래서, 가장 최초의 리눅스를 분석하기로 했다.
운영체제로 동작하는 최초의 리눅스는 1991년에 리누스 토발즈가 minix를 기반으로 개발한 리눅스 0.01버전이다.

나와 같은 관심사를 가지고 있는 현업의 프로그래머들이나 이제 막 운영체제 이론을 배우고 있는 학생들에게도 도움이 될 것 이다. 다만, 컴퓨터 구조를 포함한 기본적인 CS지식과 초급 이상의 C 언어 프로그래밍 능력, 그리고 영어를 읽을 수 있다면 나와 함께 진행하는데 큰 무리는 없을 것 이다.

> 코드를 이해하기 위해 꽤 많은 영문 레퍼런스 매뉴얼을 읽었어야 했다...

리눅스 0.01분석 포스팅은 여러 시리즈로 작성될 것 같고, 최종 목표는 컴퓨터 부팅 시점부터 리눅스 커널의 유저영역 프로그램이 "Hello World!"를 터미널에 출력하는 전 과정을 이해하는 것이다.

이번 포스팅에서는 리눅스0.01버전을 빌드하고 애뮬레이터를 사용해서 실제로 동작시켜볼 예정이다.
또한 모든 연관 포스팅은 개인  의 내용을 기반으로 설명한다.

## 원본 버전으로 부터의 주요 변경점
이제 직면하는 첫번째 관문은 리눅스 0.01 소스코드는 어디에 있고, 어떻게 빌드할 수 있을까 이다.

2026년 현재 사용하는 컴파일러와 개발도구들은 리눅스 0.01을 빌드하기 힘들다.
GCC가 아무리 하위 호환성을 가지고 버전업을 하더라도 30년이 넘은 코드를 빌드시켜줄리는 없다.

> 리눅스 0.01 버전 빌드에 사용한 GCC는 xx 버전으로 알려져 있다.

처음엔 커널 소스코드를 수정하여 빌드하는 것 까지 직접 하려고 했으나, 들이는 시간과 노력에 비해 결과가 미비하여 과감히 생략하고 분석과정에만 집중하기로 했다.

다행히 전 세계의 뛰어난 프로그래머들이 이미 컴파일 가능 하도록 수정한 버전을 찾을 수 있었다.
참고한 원본 Github 저장소는 [이곳]()이다. 그리고 [이곳]()도 참고했다. 각 링크에 접속해보면 알 수 있겠지만 꽤 유사하다. 사용하는 파일도 겹친다. 그래서 최초의 제작자가 누구인지 정확히 알 수 는 없으나 

아래는 리누스 토발즈가 작성한 원본 버전과 비교하여 변경된 부분과 내가 예상하는 그 이유를 간략히 설명한다. 

### 컴파일 호환성 확보
최신의 컴파일러로 빌드하기 위해 인라인 어셈블리와 어셈블리 주석, 그리고 컴파일 옵션등을 다수 수정했다.

### 하드디스크 레이아웃 변경
리누스 토발즈가 리눅스 0.01을 만들 당시에는 [CP3044](https://www.computerhope.com/hdd/hdd0036.htm) 하드디스크를 사용했다.


### 파일포맷 및 로더 변경
가장 크게 느껴지는 변경점 중 하나이다. 1991년 당시 리눅스 0.01과 Minix는 `a.out` 파일 포맷을 사용했다. 컴파일된 재배치 가능한 오브젝트 파일이나 실행파일 등은 모드 해당 파일 포맷을 사용했기 때문에 커널 로더도 `a.out` 포맷을 파싱하도록 구현되어 있다. (현재는 알다시피 ELF 포맷이 주류다.)

문제는 `a.out`포맷을 출력 결과물로 생성하는 마지막 GCC버전이 xx라는 것 이다.
즉, 현대 컴파일러와 툴체인에서는 리눅스 0.01 커널이 실행할 수 있는 바이너리를 생성하는 것 조차 어렵다. 그래서 아예 커널 로더를 ELF포맷을 파싱하도록 변경한 것 으로 보인다.

### 디스크 이미지 재생성
이 부분은 `hd_oldlinux.img` 파일이 블랙박스인 점이 마음에 들지 않아서 직접 변경했다.
전에 언급한 참고 링크에서도 해당 파일을 그대로 사용하고 간략한 설명만 있을 뿐(물론 이 설명마저도 부정확했다..), 어떤 파일인지 명시된 자료와 코드를 찾을 수 없었다.

분석 결과 애뮬레이터에서 사용하기 위한 하드 디스크 이미지 파일이고 내부에는 리눅스 0.01 용으로 포팅된 셸과 명령어들이 있었다. 이 디스크 이미지에 관한 자세한 내용은 다른 포스팅에서 다룰 예정이다.

## 컴파일 하기
리눅스 0.01의 컴파일은 아주 간단하다. 단순히 `make` 명령 한번이면 커널을 빌드하고 부팅 디스크 이미지까지 만들어 준다.

> 알다시피 최신 리눅스 커널은 빌드 가이드가 따로 필요할 정도다.

테스트된 컴파일 환경은 다음과 같다.
|       | Version              |
| ----- | -------------------- |
| OS    | Ubuntu 22.04 / 24.04 |
| GCC   | 11.04 or later       |

아마 정확히 같지 않더라도 대부분의 데비안/우분투 기반 리눅스에서는 정상빌드 될 것이다.
참고로 다른 배포판은 확인해보지 않았으니 혹시 독자 중에 시도해본 사람이 있으면 공유해주면 좋을 것 같다.

소스코드는 [Github저장소](https://github.com/seojuncha/linux-0.01-revival) 에서 다운로드한다.
```bash
git clone https://github.com/seojuncha/linux-0.01-revival
```
리눅스 소스코드가 있는 `linux-0.01`디렉토리로 이동해서 `make`명령을 실행한다.
```bash
cd linux-0.01
make
```


## Bochs 애뮬레이터 사용하기
리눅스 커널 바이너리는 준비되었다.
이 커널을 어떻게 실행할 수 있을까? 
우리는 [Bochs](https://bochs.sourceforge.io)라는 x86 환경 중심의 애뮬레이터를 사용한다.

> [QEMU]()도 훌륭한 애뮬레이터다. 하지만, 최신버전의 QEMU로 테스트 해봤을 때, Bochs 보다 사용성이 훨씬 부족했다. 무엇보다 디버거 연동이 엉망이었다.

이미 앞서 커널소스코드를 컴파일 하였기 때문에, 다운로드 받은 소스코드 디렉토리에서 디스크 이미지를 압축해제한 뒤에 바로 에뮬레이터를 실행할 수 있다. 

```bash
tar -xzf hdb.img.tar.gz
```
`hdb.img`파일과 `linux-0.01/Image` 파일 두개를 사용해서 Bochs애뮬레이터를 실행한다.
해당 내용은 Bochs 설정파일인 `bochsrc.txt`파일에 명시되어 있다.

## 체험하기
이제 터미널에서 `bochs -q -f bochsrc.txt`를 실행하면 새로운 GUI 창이 나타나고 터미널은 Bochs 로그와 함께 내장 디버거 세션에 진입한다.

> 혹시 리눅스 데스크탑을 사용하지 않는 경우에는 X11 포워딩을 하면 된다. WSL2에서 테스트했고, 리눅스 머신에 ssh 접속한 macOS에서도 동작하는 것을 확인했다.

애뮬레이터 최초 실행시점은 실제 물리 컴퓨터에서 전원 버튼을 누른 직후라고 생각하면 직관적이다.
그 때문에 터미널의 내장 디버거는 CPU의 [리셋벡터]() 위치에서 자동으로 멈춘 상태로 시작한다.
곧 다른 포스팅에서 간단히 Bochs내장 디버거 사용법을 살펴 볼 예정이므로, 지금은 디버깅 세션에 `c`를 입력하여 계속 진행한다.
