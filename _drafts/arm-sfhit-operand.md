오늘은 ARM 데이터 처리 명령어(Data Processing Instructions)의 시프트 피연산자(Shifter Operand)총정리를 위한 포스팅입니다.
시프트 피연산자는 모든 데이터 처리 명령어에서 필수로 사용되는 중요한 내용입니다.

시프트 피연산자의 종류와 유효한 어셈블리 코드를 작성하는 방법을 예제와 함께 살펴보고 ARM에서 시프트 피연산자를 제공하는 이유를 알아보겠습니다.

## 시프트 피연산자의 활용
`mov`와 `add`와 같은 모든 데이터 처리 명령어는 최소 하나의 시프트 피연산자를 사용합니다.
그리고 항상 목적지 레지스터(Rd)와 입력 피연산자를 최소 1개 이상 사용합니다.
이 때, 하나의 피연산자는 항상 레지스터이고 다른 하나의 피연산자는 시프트 피연산자입니다.

![A3.4 Data-Processing instructions]()

### 데이터 처리 명령어 포맷
어셈블리 프로그래밍도 다른 프로그래밍 언어와 같이 문법에 맞게 작성해야 합니다.

![데이터 처리 명령어 포맷]()

- `mov`와 `mvn`일 경우:
  - `<instruction> <Rd>, <Shifter Operand>`
- 그 외 경우(`add`, `sub`, 등):
  - `<instruction> <Rd>, <Rn>, <Shifter Operand>`

정리하자면, `mov`은 `mvn`은 `<Shifter Operand>`를 `<Rd>`에 저장하는 단항 연산자이고
그 외 명령어들은 `<Rn>`과 `<Shifter Operand>`를 연산한 결과를 `<Rd>`에 저장하는 이항 연산자입니다.

## 시프트 피연산자의 종류
시프트 피연산자의 포맷은 다시 다음과 같이 분류할 수 있습니다:
- 즉시값: 
  - `#<immediate>`
- 레지스터값: 
  - `<Rm>`
- 시프트 값:
  - 왼쪽 논리 시프트 시프트
    - `<Rm>, lsl #<shift_imm>`
    - `<Rm>, lsl <Rs>`
  - 오른쪽 논리 시프트
    - `<Rm>, lsr #<shift_imm>`
    - `<Rm>, lsr <Rs>`
  - 산술 시프트
    - `<Rm>, asr #<shift_imm>`
    - `<Rm>, asr <Rs>`
  - 순환 시프트
    - `<Rm>, ror #<shift_imm>`
    - `<Rm>, ror <Rs>`
    - `<Rm>, rrx`

`<Rm>`은 데이터 처리 명령의 피연산자 중 1개로 사용되는 레지스터를 의미합니다. (다른 1개는 `<Rn>`입니다.)
`lsl`이나 `asr`과 같은 시프트 연산자의 오른쪽에는 시프트되는 양(즉시값 혹은 레지스터값)을 표기합니다.

이전 섹션에서 표기한 전체 명령어 포맷에서 `<Shifter Operand>`를 위 내용으로 치환할 수 있습니다.
예를 들어:
```
# mov r0, r1
  <instruction> <Rd>, <Shifter Operand>
  <instruction> <Rd>, <Rm>
       mov       r0    r1
 
# add r0, r1, r0, lsl #2
  <instruction> <Rd>, <Rn>, <Shifter Operand>
  <instruction> <Rd>, <Rn>, <Rm> lsl #<shift_imm>
       add       r0    r1    r0         #2
```

### 문법 예제

```armasm
mov r0, r1           @ 유효(<Rd>=r0, <Rm>=r1)
mov r0, #0xff        @ 유효(<Rd>=r0, <Shifter Operand>=0xff)
mov r0, r0, lsl #2   @ 유효(<Rd>=r0, <Sfhiter Operand>=r0, lsl #2)
add r0, #1           @ 무효(<Rd>=r0, <Rn>이 없음)
```

## 즉시값의 범위
시프트 피연산자 값으로 즉시값(`#<immediate>`)을 사용할 때 주의해야 할 것이 한가지 있습니다.
32비트 ARM프로세서이기 때문에 `0x0` 부터 `0xffffffff` 까지의 데이터를 다룰 수 있다고 생각하지만,
모든 32비트 값을 시프트 피연산자의 유효한 즉시값으로 사용할 수 는 없다는 것입니다.

예를 들어, 
```armasm
  .text
  .global _start
_start:
  mov r0, #0x101
  b .
```

즉시값 `0x101`은 `257`이지만 컴파일 오류가 발생합니다.
```
imm.s: Assembler messages:
imm.s:4: Error: invalid constant (101) after fixup
```

### 즉시값 인코딩
어셈블리 코드를 이진데이터로 인코딩할 때, 즉시값은 12비트 영역을 사용합니다.

```
<rotate amount> = 2 * #<rotate_imm>

0x00 <= #<imm_8> <= 0xff(255)
0x0 <= #<rotate_imm> <= 0xf(15)
```

```
#<immediate> = #<imm_8> ROR (2 * #<rotate_imm>)
```

### 즉시값에 순환시프트를 사용하는 이유
32비트 ARM프로세서에서 모든 명령어 크기는 32비트입니다.
32비트 영역안에서 opcode와 레지스터 정보등을 모두 사용해야 하죠.
만약 즉시값 자체를 32비트를 모두 사용해서 표현하면 명령어 전체가 64비트가 되어야 합니다.
그럼 다른 명령어들과 일관성이 떨어지고 명령어가 복잡해져 ARM의 설계철학과 맞지 않습니다.

그리고 우리가 프로그래밍할 때 사용하는 대부분의 상수값을 생각해보면 아래의 3가지 정도입니다.
- 작은 상수
- 비트 마스크
- 포인터 오프셋

결국 8비트 상수와 4비트 순환시프트라는 절충안으로 최대한의 상수를 표현할 수 있습니다.
